# Explainable Dementia Classification: A Reproducible ML Evaluation

**Musa Hanafi · Python · scikit-learn · XGBoost · Streamlit · SHAP**

> SYNTHETIC DATA DEMONSTRATION. This project evaluates software and modeling workflow, not clinical efficacy. It classifies **same-visit CDR status**, not future Alzheimer's risk.

## Why this project

A high score is useful only when the data, evaluation protocol, and result can be inspected. This revision audits an existing prototype, fixes evaluation leakage, and produces one consistent run report from saved metrics.

### What it demonstrates

- Data provenance and cohort validation with SHA-256 input tracking.
- A participant-disjoint development/holdout split.
- Fold-local median imputation and scaling with explicit predictor allowlisting.
- A prevalence baseline, logistic regression, random forest, and XGBoost comparison.
- Development-only hyperparameter selection, calibration, and decision-threshold selection.
- ROC/PR analysis, confusion counts, calibration, conditional bootstrap intervals, and subgroup errors.
- Training permutation importance and a clearly scoped SHAP example.
- A tested Streamlit app, a self-contained report, integrity tests, and a GitHub Actions workflow.

## Verified included run

**Dataset:** 317 synthetic visit rows, 150 subjects. Latest observed visit retained per subject. **Development:** 120 subjects. **Holdout:** 30 subjects (12 positive). Seed 42. Selected base model: **xgboost**, followed by prespecified sigmoid calibration.

Threshold: **0.42**, chosen from development out-of-fold probabilities under recall >= 0.80, maximizing precision. Test confusion counts: TN=17, FP=1, FN=2, TP=10. The development recall target is not a test-set guarantee.

Intervals use 1,000 stratified holdout resamples with a fixed model and fixed class counts. They do not capture retraining uncertainty. See the model card for limits of development OOF threshold selection after hyperparameter selection.

## Study design

**Question:** can a tabular classifier distinguish CDR = 0 from CDR > 0 at the same observation?

**Cohort:** one latest observed visit per subject. This prevents cross-fold participant overlap without pretending that latest-visit classification predicts future progression.

**Predictors:** Age, EDUC, SES, MMSE, eTIV, nWBV, ASF, and sex category encoding. CDR, Group, IDs, visit sequence and administrative columns are excluded.

**Protocol:** 80/20 stratified subject split; five-fold grid search on development data; selected non-dummy model by development ROC-AUC; training-only sigmoid calibration; threshold selected from development OOF probabilities; final holdout evaluation.

**Why no SMOTE?** This revision uses no resampling. Class weighting is used for logistic regression and random forest. It removes the original pre-CV oversampling issue and keeps the benchmark easier to inspect.

**Interpretation:** feature importance is not causality. The SHAP example explains the selected raw, uncalibrated estimator; it is not a decomposition of the final calibrated prediction.

## What changed from the original

The previous repository contained a ZIP with inconsistent README and saved-model scores. This revision does not claim to reproduce those older scores. The current result is independently regenerated with a documented protocol. See [the audit](docs/AUDIT.md).

## Limitations

- Bundled data is synthetic; its generator is not included in the source archive. Fidelity to OASIS is not verified.
- MMSE and CDR measure related constructs; this can make the task less meaningful than clinical prediction.
- Only 30 holdout subjects; subgroup results are descriptive, not evidence of fairness.
- No external clinical validation, pathology confirmation, future-risk modeling, or production deployment is claimed.
- Grid-search selection CV and later development OOF diagnostics are not fully nested unbiased estimates. The holdout is kept separate from model choices.

## Real-data extension

Obtain appropriately authorized data and record the source citation. Place local files under the ignored `data/private/` directory, run with `--data-kind real --source ... --output reports/real/<run>`, and independently review the study design. The software will reject the bundled synthetic file if it is labeled real. Real-data per-subject predictions are not exported by default.

OASIS-2 source information: https://dev.oasis-brains.org/ (150 subjects and 373 imaging sessions in the original dataset, distinct from this synthetic CSV). Review provider terms and citations before obtaining or distributing data.
